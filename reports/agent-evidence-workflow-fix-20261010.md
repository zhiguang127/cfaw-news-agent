# Agent证据准备与判断流程优化（2026-10-10）

用户反馈保存已正常，但报告反复缺少正文，把信息缺失推导为“本周无需学习”，并显示当轮E标签和内部字段。本轮修改证据准备、判断约束和核实交互，保留现有用户记录；没有调用真实模型、修改模型配置或推送发布。

## 明确原因与实施

1. 普通关注动态原先只补读具有日期和地点的日程候选；目标关注没有进入正文补读。现在目标候选进入补证据队列，日程风险优先、无摘要目标候选其次，其他目标候选按召回顺序补读。每轮仍最多两次网页请求，单篇15秒及整轮准备45秒保护保留。
2. 追踪未利用阅读器已支持的来源RSS/Atom正文，网页提取也未传来源URL，少数派专用SSR分支无法生效。现在利用全部候选中提供的RSS/Atom正文，不占网页请求额度；网页提取传来源URL。正文缓存最多8条，与候选上限一致，避免读取完后在组装快照前淘汰前面的证据。
3. 原先首段超过4KB时直接退出，可能整篇变成没有正文。现在过长首段保留最多1000个Unicode字符，最多六个非空段落、合计4KB UTF-8，并标记截断。仅向Agent提供真实片段，未冒充全文或自动生成全文摘要。
4. 新提示词 `tracking-v2.4` 区分仅有标题、标题与摘要、正文片段；缺少信息不推导没有值得试的工具，也不取消用户学习时间。仅有标题的目标判断须unknown、具体待核实项和next_step；全部目标判断仅有标题时须insufficient_evidence。用户说明出现内部字段会进入原最多一次修正。来源摘要足够支持有限结论时仍允许判断；确定性约束不能证明所有语义结论正确。
5. 分析页新增“补充正文并重新判断”：保留当轮目标、版本和候选范围，优先重试最多两篇被引用但缺失正文的报道，绕过失败读取的5分钟自动重试冷却。新快照明确标作targeted_verification，不冒充重新搜索全部新闻。证据没有变化时保留原outcome，避免把证据不足统一改作no_change。
6. 展示先呈现本次判断，再提供上次对照；没有新增依据但仍未知的判断继续可见，不增加重复未读提醒，已处理和忽略决定仍受保护。E标签按各自轮次解析为文章标题，旧内部标记转为自然语言；标题、摘要、已读取但未引用的片段和精确正文引用分别标注。详情页保留当时的证据版本，不能把当前网页冒充当时引用。
