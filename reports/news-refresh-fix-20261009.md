# Windows 新闻刷新修复

## 原因与修改

在隔离的 Rinx 原生测试宿主中复制现有账户数据，运行完整启动流程，旧代码出现 `script time budget exceeded`，定位到日程校验。收藏、追踪状态、日程、分析历史等八个仓库加载原先在同一回调中执行，累计超过宿主的 64 ms 时间限制，后续初始化未完成。初始化中断后的刷新界面不能代表正常网络请求状态。

`src/app/startup.splash` 现按顺序分段执行加载，每个仓库获得新的回调时间片，全部加载完成后继续原有初始化与逐源缓存恢复。没有增加计算预算，也没有删除用户数据。`scripts/test_live_news.py` 可测试单源真实联网，或使用 `--startup --copy-data <目录>` 在隔离副本中测试完整启动；测试探针支持多个明确获准的网络主机。

## 验证

- 修改前：隔离副本启动中断，零新闻，宿主记录超时错误。
- 修改后：按正式 manifest 网络白名单完成 17/17 个源刷新，`busy=false`、`active=0`，显示 130 条新闻；7 个源为 fresh，10 个源记录真实超时、网络错误或 HTTP 429。失败来源计入完成进度，不补造新闻。
- 完整启动验证目录：`.test-state/live-news-hn-1791553705491573900`；宿主日志无 `[E]` 错误。
- `assemble.py --check` 通过；Rinx 编译后的原生 contract 校验包摘要通过；ZIP 的主脚本及 manifest 与 bundle 逐字节一致。
- 新摘要：`d431f21f8e8039cc4356d83ae89d4e7f9d222b9688293c4d5e3ee6fc42dccafd`。

原账户存储只用于读取并创建测试副本。测试不调用模型；这里的结果证明新闻启动与刷新流程，并不证明模型分析质量或每个公开来源始终可访问。用户正在运行的旧实例需要退出并从更新后的 bundle 重新 Review / Run。
