# 运行时提示词

`catalog.json` 是运行时提示词的唯一登记入口，包含模板常量名、UTF-8 文本文件和版本常量。模板分别覆盖关注理解、日程理解、追踪分析、一次性输出修正和连接诊断。

修改对应 `.txt` 文件后运行 `scripts/assemble.py`，再通过 `scripts/package.py` 刷新 bundle 完整性并生成导入包。组装器将模板转为转义后的 OctoScript 字符串常量，在调用者之前加载；运行时不读取这些源文件，也不需要额外权限。不要直接修改生成的 `bundle/main.splash`。

初次提取保留模板内容与版本；生活场景优化将追踪分析和关注理解升级为 `tracking-v2.3`，保留时间、预算、技能和产品约束，区分可用功能、宣传与实测，强调适用范围和澄清导致的判断更新。后续改变提示语义时更新 `catalog.json` 中的关联版本：追踪分析使用 `tracking_prompt_revision`，关注理解单独使用 `intent_prompt_revision`（当前 `intent-v1.1`），日程理解使用 `schedule_intent_prompt_revision`。关注理解补齐字段类型与Unicode字符限制，并使用 `intent-repair-prompt.txt` 在原截止时间内最多纠正一次；保留用户约束，仍需核对预览并确认保存。追踪修正模板随追踪版本维护，连接诊断仅验证连通性。

版本变更后，旧结果不再作为当前有效建议展示，保存的关注、日程与用户决定不删除；重新检查后生成当前结果。结果 schema 仍为 2，现有引用校验、短标签展开和最多一次修正保持不变。提示词要求不是模型质量保证，实际结果仍需通过结构、引用和版本校验，并供用户核对。

当前追踪版本为 `tracking-v2.6`：明确区分标题、来源摘要和有界正文片段，缺失证据不推导“不值得试用”或取消学习时间；可能相关的缺失正文建议具体核实。用户说明不得输出内部字段或当轮E标签。仅有标题的目标判断及内部诊断另有确定性校验，可触发原一次修正；保留摘要足够支持有限结论的路径。核实范围字段避免将针对上轮候选的补读描述为全面检索。

`news-impact-v1.md` 是旧分析契约的参考说明，不是当前模型请求模板；旧记录的 `analysis_prompt_revision` 仍在 `agent/context.splash` 中用于兼容和校验。

`tracking-v2.5` 将当前情况汇总置于建议之前：区分本期报道与上次已知事实，新闻跟踪不默认变成购买决策。每项目标的引用须对应非无关、关联该目标的条目；无相关新闻可返回空引用，但只能报告证据不足，不能声称新增事实或重新打开决定。unchanged 的变化依据必须为空。

`tracking-v2.6` 进一步区分候选召回与确认相关：来源、分类和泛行业词命中不能直接证明目标关联；命名品牌或产品须有具体联系，实用目标须涉及其任务、功能、访问条件或限制。证据不足以确认关系时返回 uncertain，不把同批候选关联到所有目标。结果解析继续展开短证据标签、校验正文引用、当前情况与目标判断；提示词中的相关性要求仍需用户结合原始证据核对。
