# CFAW News

**让新消息，与你的下一步有关。**  
NEWS THAT MOVES YOU

CFAW News 是运行于 **Rinx** 的新闻 Agent 应用。用一句话告诉它你想做什么，它整理你的目标与约束，从真实新闻中寻找相关变化，给出有依据的下一步建议。你可以查看来源与原句、修正它对意图的理解，并决定继续观察、处理或不采纳。

作品关注一个具体问题：**这条新消息，是否值得我改变下一步？**

## 从信息流走向自己的目标

每天都有新工具、新产品和新规则，但“消息很多”并不等于“知道该做什么”。同一条 AI 新闻，对每周只有两小时的学习者、预算有限的换机用户和关注家人照片隐私的人，意义可能完全不同。

CFAW News 把**个人意图、新闻证据、判断历史、用户决定和应用内日程**连接起来：

1. **表达意图**：写下目标、使用场景和限制，Agent 整理成可以确认和修改的关注。
2. **检查变化**：从启用来源获取新闻，为每个话题寻找相关报道，判断它与目标的实际关系。
3. **解释依据**：展示目前情况、下一步建议、未知条件，以及实际引用的报道和原句。
4. **由用户决定**：记录观察、已处理或不采纳；明确希望安排试用时，查看任务与建议时段，批准后一键保存日程。
5. **继续跟踪**：结合上次判断与用户决定检查后续变化，必要时更新或撤回建议。

### 从建议到日程：一次批准即可保存

用户可以像日常聊天一样输入：

> 我用 Mac 开会和做 PPT，想试一个能省时间的 AI 工具。每周只有两小时，帮我安排一次简单试用。

## 从建议回到证据

关注卡片按“**目前情况 → 建议下一步 → 查看依据**”呈现。进入判断依据页，可以核对：

- 为什么这条报道与当前目标有关；
- 当时使用的来源摘要和保存的正文片段；
- 对应的原文段落、原句与来源地址；
- 哪些适用条件尚未确认，哪些材料只提供了标题或摘要。

## 把天气带入日程判断

保存带有明确城市地点的日程后，应用会匹配该城市与日程日期的有效预报，交给同一个 Agent 与日程、候选新闻一起分析。即使这次没有相关新闻，也可以根据真实预报给出通勤与物品准备建议。

| 录入真实安排                                                                                | 查看天气准备建议                                                                                                      |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| <img src="docs/images/final/schedule-form.png" alt="录入南京项目讨论的地点、日期和起止时间" width="330"> | <img src="docs/images/final/schedule-weather-advice.png" alt="已保存的南京项目讨论日程显示 Agent 给出的带伞及资料防水建议" width="330"> |

例如，室内会议当天的预报有降雨，Agent 可以提醒带伞、保护电脑和资料，并在临近出发时核对逐小时天气。判断使用日程所在地的预报，天气页切换到另一个城市不会替代日程地点。

每条建议须对应当前日程版本和预报标识。展开“核对行程与消息覆盖”可以查看预报日期、来源与获取时间；日程或预报变化后，旧建议失效。线上会议、地点含多个城市、过期预报或缺少对应日期时，不套用不匹配的天气。

日预报只支持准备和复核，不能据此断言会议时段必定下雨，也不会自行取消、改期或修改已经确认的日程。

## 作品如何实现

界面与业务使用 **OctoScript / Makepad**，通过 **Rinx 管理的 Octos** 调用应用 Agent。团队演示使用 MiniMax；模型与凭据由宿主管理。

```mermaid
flowchart LR
    U[用户意图与约束] --> C[整理、编辑、确认]
    C --> R[话题召回与 BM25 排序]
    N[真实新闻来源] --> E[获取、去重、缓存与正文证据]
    E --> R
    W[日程城市与日期的有效天气预报] --> A
    R --> A[Agent 判断关系与变化]
    H[上次判断与用户决定] --> A
    A --> V[结构、引用、版本校验]
    V --> D[解释依据与用户决定]
    D --> H
    D --> S[确认后的应用内日程]
```

| 实现重点              | 对体验的作用                                     |
| ----------------- | ------------------------------------------ |
| **一个应用 Agent**    | 负责意图整理、新闻摘要与变化判断，检索、存储和校验由应用代码完成。          |
| **目标约束参与分析**      | 预算、设备、使用场景与时间限制影响建议，避免只有泛泛的行业总结。           |
| **标题筛选与 BM25 排序** | 支持中文二元词与英文词召回，逐话题准备候选和证据；当前没有向量索引。         |
| **有界执行与恢复**       | 每个话题最多分析 8 篇候选，正文补读最多 2 篇；支持进度、取消、限时与有限纠正。 |
| **结果与版本校验**       | 检查新闻引用、正文片段和当前目标版本，拒绝失效或不完整的输出。            |
| **试用计划与一键导入**    | Agent 提议一次有依据的有限试用，应用生成并检查建议时段；用户批准后直接保存，防止重复创建。 |
| **天气与日程联合分析**     | 将匹配城市和日期的预报作为独立证据，校验天气建议，保持已确认日程。          |
| **历史与用户决定**       | 对照前次判断，保留观察和不采纳等决定，支持解释建议变化与撤回。            |
| **用户确认**          | 关注保存、核实任务和日程变更由用户确认，模型输出不会自行修改安排。          |

新闻浏览、收藏、天气和手动日程管理可独立使用；需要推理的功能依赖宿主助手与模型服务。

## 运行说明

当前交付为 **Windows / Rinx 本地导入作品**。应用 ID 为 `dev.cfaw.news`，包版本为 `1.0.0`。

### 运行环境

| 条件                | 说明                                                                    |
| ----------------- | --------------------------------------------------------------------- |
| Windows 与兼容的 Rinx | 使用包含本项目正文阅读、WebReader 和新闻内存保护支持的宿主，并完成宿主要求的账号登录。                      |
| 配套 Octos 与宿主资源    | 宿主运行目录应包含 `octos.exe`、`makepad_widgets/resources` 和 `rinx/resources`。 |
| WebView2 Runtime  | 用于 Windows 应用内图文原文阅读。                                                 |
| 网络与模型服务           | 新闻、正文与天气需要访问对应来源；意图理解、摘要和联合分析还需要可用的宿主助手。                              |

应用交付包包含 `bundle/`，宿主需要另外准备。直接导入已有交付包无需安装 Python 或 Rust；从源码构建宿主和重新打包的方法见 [运行与构建说明](docs/development.md)。

### 启动宿主并导入应用

本机已准备完整新闻宿主时，在本项目根目录打开 PowerShell，执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_news_host.ps1 -Visible
```

脚本默认使用项目根目录相对路径 `../../Rinx-main/target/release/rinx-news.exe`。宿主在其他位置时，通过 `-HostRoot` 指定 Rinx 仓库根目录：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_news_host.ps1 -HostRoot 'D:\path\to\Rinx' -Visible
```

启动后按以下步骤导入：

1. 打开 **Mini apps → Import an app**。
2. 在 **OctoSense bundle folder** 中填写本项目 `bundle/` 的绝对路径。可用下面的命令获取路径；使用 [交付 ZIP](build/cfaw-news.zip) 时，先解压再选择其中的 `bundle/` 文件夹。
3. 核对应用名称 **CFAW News**、ID `dev.cfaw.news` 和申请的存储、联网、图片、网页及 Octos 会话权限。Room 可留空。
4. 按下一节配置助手，然后执行 **Review bundle → Run** 进入应用。

```powershell
(Resolve-Path '.\bundle').Path
```

### 配置助手并测试连接

在 Rinx 的助手配置中填写自己的模型信息。团队使用的配置如下，可用性以自己的账号和宿主配置为准：

| 配置项      | 值                           |
| -------- | --------------------------- |
| Provider | `minimax`                   |
| Model    | `MiniMax-M3`                |
| Base URL | `https://api.minimax.cn/v1` |
| API key  | 自己的 MiniMax 密钥，只在 Rinx 中填写  |

选择 **Use this device**，由 Rinx 管理本机 Octos；模型仍可通过云端 API 推理。当前锁定宿主重新保存助手配置时需重新填写密钥，空密钥再次保存可能覆盖已有配置，日常启动无需重复保存。

进入应用后，打开 **我的 → 新闻来源 → 连接诊断 → 测试连接**。收到实际助手回复后，再使用意图理解、摘要提取和联合分析。新闻浏览、收藏、天气和手动日程管理可独立使用。

### 初次使用与加载更新

- 在 **我的 → 新闻来源** 选择来源并查看获取状态，返回首页刷新新闻。
- 点击底部中央加号，输入自己的目标或安排，核对理解后确认保存。
- 在 **关注** 页检查更新并查看判断依据；带有明确城市地点的日程可匹配对应日期的天气预报。
- 明确请求安排试用后，在 **话题详情 → 简单试用计划** 核对建议时段，点击 **确认并导入日程** 即可保存；打开 **日程** 查看，无需再次录入日期或时间。
- 替换应用包或修改并重新打包源码后，退出旧应用，重新 **Review bundle → Run**。关注、收藏、日程等记录保存在宿主应用存储中，更新应用无需清空这些记录。

### 常见运行问题

| 现象                                          | 处理方式                                                                  |
| ------------------------------------------- | --------------------------------------------------------------------- |
| 找不到 `rinx-news.exe` 或宿主资源                   | 核对 `-HostRoot` 指向的目录，按 [构建说明](docs/development.md#准备宿主构建环境) 准备完整新闻宿主。 |
| `bundle digest does not match the manifest` | 使用完整交付包，或通过打包脚本刷新摘要，再重新 Review / Run。                                 |
| 助手未启用、模型鉴权或连接失败                             | 核对 Rinx 助手配置、密钥、模型 ID、Base URL 与连接诊断反馈。                               |
| 新闻、天气或正文读取失败                                | 在来源或天气页查看具体状态，核对网络；正文受限时通过应用内原文页阅读。                                   |

完整的宿主准备、源码组装、打包命令与故障处理见 [运行与构建说明](docs/development.md)。

## 体验范围与数据说明

- **跟踪在应用运行期间进行**，尚未提供关闭后的后台推送、跨设备同步或系统日历写入。
- **来源与正文存在访问条件**。登录、订阅、人机验证和网络问题可能限制读取；能在原文页看到内容，不等于 Agent 已获得该正文。
- **天气使用城市日预报**，依据日程的明确地点匹配城市；不读取设备定位，不提供会议时段的实况保证。
- **建议需要判断与核实**。引用和结构校验有助于追溯依据，不保证报道或模型解释一定正确。
- **模型推理可能经过云端**。相关输入、目标、日程和候选证据通过宿主发送给配置的模型；详见 [隐私说明](PRIVACY.md)。
