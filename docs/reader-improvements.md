# 图文阅读改进与验证（2026-10-06）

本轮修改位于 cfaw-news-agent-new.2，使用 D:\Hackathon_agenticapp\Rinx-main 的原生库验证。应用外层保持自适应，不恢复此前已回退的固定手机画布。

## 已完成

- 正文按网页顺序保留段落、二至四级标题、简单列表、引用、配图和图注。优先选取正文容器，排除导航和相关报道区域；部分网站封面在正文外，使用 og:image 补充。
- 正文字号 17，行距 1.35，两端对齐：英文展开词间距，中文展开字间距；不修改原文字符，段落最后一行及手动换行保持左对齐。正文段后额外留白 14，与容器间距合计约 32；标题字号 26。标题、图注、列表和引用保持原对齐。宽窗口正文栏最大 720，窄窗口填满可用宽度并留左右边距。图片按原始比例适配宽度。
- 原文链接放在标题下方。无摘要、未支持来源、网络失败或提取失败时仍可打开原文；受支持来源保留重试读取按钮。
- 打开另一篇新闻重建其滚动容器，从标题开始；图片到达时保留当前阅读位置。旧请求的回调由 generation 检查隔离，避免离开后串图。
- 图片 HTTPS 请求使用明确的来源/CDN 域名列表、有界重定向和超时；拒绝非图片文件头。最多 6 张，单图 2,000,000 字节，合计 6,000,000 字节，逐张加载。未获准、超限或失败的图片不会阻止正文阅读。
- 组装脚本与 manifest 同步申报图片 CDN。Agent 的正文证据仍只保存段落，不将图片资源写入持久记录或模型输入。

## 如何验证

1. 完整退出旧 Rinx，运行 D:\Hackathon_agenticapp\Rinx-main\launch-rinx.cmd。
2. 在 Mini apps 中重新 Import an app，选择 D:\Hackathon_agenticapp\workspace\cfaw-news-agent-new.2\bundle，Review bundle → Run。若使用 ZIP，选择 build/cfaw-news.zip。重新审核网络权限，沿用现有 MiniMax 配置。仅重启旧应用不会替换它已导入的代码。
3. 首页刷新后点击 MIT 等受支持来源的“查看”。应出现“来源网页 · 图文阅读模式”，正文与图片；图片可能稍晚到达。滚动查看标题层级、段落间距、图注及配图比例。
4. 将窗口缩窄和放宽。外层仍填满宿主，正文在宽窗口居中且不过宽，窄窗口正常换行。不要按旧的 430×860 固定画布验收。
5. 阅读到中间后返回，再打开另一篇。应从新文章标题开始；旧文章的图片不能出现在新文章内。
6. 对不支持正文、无摘要或网络失败的条目，标题下应始终能看到“打开图文原文”。实际点击应在系统浏览器进入该条目的网址，查看原站图片及完整排版。没有摘要时应明确提示。不要以所有来源都能提取全文作为通过条件。
7. 受支持来源失败后点击“重试读取正文”。图片失败不应导致整篇正文消失，分析、收藏和返回入口仍应可用。

真实图文检查使用：https://news.mit.edu/2026/astronomers-catch-star-slowly-snacking-on-brown-dwarf-1005 。这是单站烟雾验证；验证其他失败条目时请记录原文地址和错误文字。

## 已执行的检查与限制

新版 Rinx 的隔离原生 App 测试：430×860、800×1050 两种窗口，检查图像真实像素、合成图片比例、正文顺序、标题/列表/引用/图注、正文宽度、未授权图片过滤、无摘要原文入口及旧图片回调隔离。真实 MIT 网页与 JPEG 配图也已通过原生网络和显示检查。测试无账户、无模型调用，不改变用户数据；日志无 [E]。证据在 reports/b-delivery/reader-followup/，脚本为 scripts/test_reader_ui.py。

上一轮只检查了原文入口存在，未实际点击，遗漏了 Makepad 的 Windows open_url 尚未实现。本轮增加 ShellExecuteW HTTP(S) 调用，已补充真实点击检查；浏览器结果以 Windows 调用是否成功和用户最终页面为准。Windows 当前宿主没有可用的内嵌网页浏览器，因此完整原站通过系统浏览器打开。应用内阅读是结构化提取，不能复刻所有网站的 CSS、交互、付费正文或反爬页面；超限图片和复杂表格等也可能省略。真实 MiniMax 分析不在本轮检查范围内。

## 宿主补丁与重建

本次链接修复和 Label.justify 需要配套宿主，单独导入 bundle 到未修复的旧 Rinx 不会获得这些能力。本机 Rinx-main 已重编译；当前运行实例占用了原 rinx.exe，Cargo 最后替换该文件时失败，但链接产物已成功生成，因此将新产物独立保存为 target/release/rinx-reader.exe。已有三个启动入口都通过根目录 launch-rinx-main.ps1 指向此文件。完整退出旧实例再启动即可，无需自行复制覆盖占用中的文件。修改只对声明 justify: true 的正文 Label 生效，其他界面继续使用原布局；最终行不拉伸，复杂 RTL 排列保留原样。

补丁脚本 scripts/patch_reader_host.py 对固定 Makepad 源码做有明确锚点的幂等修改，保留在项目中。需要恢复或在队友机器重建时，准备当前固定依赖和 VS x64 工具链，退出 Rinx，然后运行 scripts/build_rinx_main_reader.ps1 -HostRoot D:\Hackathon_agenticapp\Rinx-main。日志位于 Rinx-main/build-reader-host.log。Cargo 的 Git 依赖不会仅凭修改时间自动重建，脚本先清理受影响的包产物；不要只重新打包 app 而省略宿主重建。

本轮通过中英文窄窗口实际像素检查，确认正文非最终行接近阅读栏右边缘、最终行保留自然宽度；真实 MIT 新闻原文入口已实际点击，日志记录 Windows ShellExecute 成功接收系统浏览器打开请求。独立 rinx-reader.exe 用空白数据目录启动与退出通过；不访问真实账户。证据在 reports/b-delivery/reader-alignment-followup/，不等同于对浏览器内文章网络加载成功的检查。

给队友 A：无需等待新模型协议即可使用此阅读页。保持已有 news source_url、summary 和 paragraphs 证据契约；不要把 UI 的图片 resource 句柄放入持久存储或提示词。新增来源时需同时维护正文选择器、图片域名和 manifest 网络申报，再通过 scripts/package.py 正规 stamp 打包。
