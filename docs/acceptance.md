## 当前实现

| 范围 | 能力与边界 |
| --- | --- |
| 新闻浏览 | 真实来源、独立缓存和错误、时间排序、同链接去重、分类/搜索、详情、收藏；顶部“首页 / 日程”导航，收藏从菜单进入，切页保留筛选。首页只有一个搜索框；筛选后按有效且未忽略的日程影响、关注相关报道、普通新闻稳定分组，组内保持原时间顺序且同报道只显示一次 |
| 启动与更新 | 只恢复启用源缓存，8 ms/最多 64 条分批处理；合并来源完成后的更新，失败保留缓存且不重排。启动刷新缺失或至少 5 分钟的来源，上拉刷新全部启用源；状态保留已有新闻数和来源进度，进行中重复上拉不取消或重启任务 |
| 关注 | 独立意图面板支持提交、至多一次关键追问、理解预览、确认、取消、重试及补充。保存原话、目的、范围、偏好、ID、版本和独立草稿；修改先预览，支持暂停/恢复和重开草稿。旧来源、主题、关键词记录仍参与内部召回，不显示规则编辑器或匹配提示 |
| 意图入口与旧预设 | 彩色工作台串联表达意图、确认关注和查看变化；不再自动添加预设。旧版未修改的预设不展示、不参与目标召回，已编辑记录保留；原数据文件不删除 |
| 新闻阅读 | 点击新闻先进入标题、来源与正文阅读页，受支持域名通过宿主 HTTP 提取文章容器段落，最多 80 段/24 KB；失败或不支持时明确显示 RSS 摘要与可复制地址。Agent 分析折叠，关联提示直接打开分析；阅读文本不自动成为模型证据 |
| 新闻影响分析 | 单个应用 Agent 整理召回词；BM25 初筛标题及有界摘要，LLM 判断目的/偏好相关性、变化及实际日程影响。每次至多 2 个目标、8 条候选，后续触发轮换，明确遗漏；保留至多 12 次缓存检查。执行提示词在 `agent/prompts/tracking.splash`，revision `tracking-v1.1`；分析仍只依据标题/有界摘要，无向量索引或本轮日程动作 |
| 请求与检查反馈 | 保存关注/日程、缓存恢复和整轮刷新结束触发有限检查；绘制和单源回调不调用模型。区分无目标、无候选、无变化、证据不足、过期、失败和取消。输入优先，取消等待宿主中断确认；关联任务及版本，拒绝迟到/重复回调；未确认中断要求重开。宿主缺服务时说明实际未接通状态，不补固定结论 |
| 提醒与决定 | 首页最多一行具体日程及原因和紧凑待关注入口；详情展示完整关系、来源、检查时间、覆盖及不确定性，可忽略或确认范围后关注这类信息。首页/详情读取同一记录。校验来源支持的事件时段与现有日程实际重合；关注、日程、证据、提示词/配置变化使旧结果失效，保存前再次核对磁盘目标及证据。无实质新事实不重现已忽略提醒；结构校验不证明模型事实正确 |
| 持久化 | 新用户记录 `topics_v2.json`（schema 2）与分析缓存 `tracking_results_v1.json`（schema 1）分开；乐观磁盘 revision 核对、有效备份、写入后核验和失败回滚。坏/未知版本文件保留，可读备份继续使用；无法恢复时明确只读。旧关注、收藏、日程和决定保持原读取路径 |
| 应用内日程 | 标题/内容/地点、北京/纽约时间、编辑、完成/取消及持久化继续可用。本轮只分析已有日程影响，不需要改期许可且不修改日程；自然语言创建/改期未实现。旧动作与决定仍可读，原确认路径继续复核证据、版本、许可与冲突 |
| 菜单与诊断 | 品牌左侧三横菜单提供来源、关注管理、关注动态、收藏、分析建议与天气；首页有轻量待处理建议入口，刷新中可停止新闻更新。连接测试收在来源页“连接诊断”中；测试只检查宿主连接，不证明业务分析正确 |
| 天气 | 品牌右侧小组件、逐日预报与选城。Open-Meteo、30 城、最多保存 12 城；当前城市持久化，旧选择文件兼容。独立恢复所选城市缓存、补取缺失/过期预报；失败显示原因和旧缓存，未知气温不补 0。位置说明卡片已删除；查询仍使用选城参考坐标，不读取设备位置。天气尚未接入 Agent |
| 其余信号接口 | 年度节假日与 CNY 基准汇率；独立校验、缓存与请求状态，未覆盖年份明确未知，取消/重复完成受保护；汇率按最新两日比较并限制支持币种。未接入页面、启动或 Agent，调用说明见 [信号接口](frontend-signal-api.md) |

天气联合分析、语义/向量检索、后台监测、通知、系统日历写入和跨设备同步尚未实现。自动检查仅为应用会话内的有限触发。包完整性、隔离原生业务、真实模型/账号导入和 App Hub 商店准入分别验证。

## 已知缺口

- BM25 仍是词法召回，查询词不足或无词面重合时会漏报；LLM 只分析候选，不替代向量索引。按同链接去重和相同标题/摘要抑制转载不代表跨报道语义归并。
- 真实 MiniMax-M3 的 `parse_intent` 已通过应用校验，账号导入/配置/Review bundle → Run 已完成；`tracking_update` 的实际判断质量、不同意图与追问、Octos 超时/中断回执尚未覆盖。执行接口和剩余样例仅维护在[开发交接](agent-integration-plan.md)。
- 本次目标 Rinx 的 PNG 抓取超时，原生控件事件通过；参考宿主 430×860 的改版截图和交互已检查，不能替代目标 Rinx 像素验收。
- 当前密钥可调用 MiniMax-M3；MiniMax-M3.1-Flash-Preview 实测返回 unknown model。测试脚本允许显式选择 Flash，按模型设置宿主推理参数，不静默切换。
- `tests/fixtures/analysis-reschedule.json` 是旧改期 fixture，缺 `schedule_id/schedule_version` 与 `allow_reschedule: true` 却标记有效，尚未接入执行入口；本轮不生成改期动作，未以新追踪测试声称该旧缺口已修复。旧 `news-impact-v1.md` 仅供历史参考，新运行路径已改用实际组装的 tracking 提示词。

## 人工验收

使用固定 Rinx 和最新未签名包，退出旧应用后 **Review bundle → Run**。模型配置见 [开发说明](development.md#5-配置-rinx-自带-octos-并测试)。参考 card-host 可查无 AI 降级与固定输入 UI；不把它当成 Rinx 服务验收。

| 操作 | 应观察到的结果 |
| --- | --- |
| 启用少量来源，刷新、搜索、关注来源、收藏并重开 | 真实新闻或具体来源错误可见；关注和收藏保留；首页没有批量分析按钮或成功/失败/跳过计数 |
| 菜单表达关注，提交示例原话，补充偏好，确认后修改/暂停并重开 | 理解结果只在确认后保存，修改不提前覆盖旧关注；原话、范围、偏好、版本和草稿恢复。取消保留草稿，失败显示原因且可重试 |
| 未设置关注/日程时检查；只添加未来日程，再检查 | 无目标引导添加；只有日程也可检查。无候选说明未调用助手，不能当成 AI 判断“无需调整” |
| 新闻正在刷新时检查，或检查过程中停止 | 刷新期间说明稍后再检查；停止后不续发剩余任务，中断未确认时明确要求重开 |
| 在相关新闻详情发起分析，期间返回动态或打开另一条，再从跟踪查看结果 | 原新闻结果仍可找到；说明依据、影响及不确定性，不自动修改日程 |
| 对同新闻再次分析，忽略已有建议后在证据未变化时再分析 | 同目标同证据不重复新增待处理项，已忽略决定保留；结果页可回看历史快照 |
| 创建未来日程并填写内容/地点，切换北京/纽约时间；保存后编辑，另建日程测试完成/取消并重开 | 时区切换保持同一时刻；内容/地点和状态持久化；完成/取消日程不占用时间 |
| 首页日程影响 → 查看依据 → 忽略 → 刷新/重开；另一次选择关注这类信息 | 首页和详情同步；相同依据不重复提示，实质新证据需解释变化。关注入口只打开范围确认，确认后关注与决定一起保存，日程不修改 |
| 提醒出现后先编辑/完成/取消日程或修改/暂停关注，再操作旧详情 | 拒绝旧版本并保留当前记录；证据缺失、过期或变化要求刷新/重分析。已有旧改期建议仍按原许可与版本规则复核 |
| 助手不可用时尝试分析或“菜单 → 新闻来源 → 连接诊断 → 测试连接” | 显示真实错误，新闻、收藏和手动日程仍可用；连接诊断平时收起 |
| 顶部天气组件选城，查看预报后返回、重开；更新失败再重试，移除城市 | 显示今日预报温度范围、降水和更新状态；主城市及城市列表保留，失败不补造天气；不显示位置说明卡片，组件加载不阻塞新闻 |
| 在新闻标题或条目区域上拉、向下拖动；更新中再上拉 | 上拉启动刷新，向下不触发；重复上拉不取消或重启刷新，失败保留旧新闻；菜单可停止新闻更新 |
| 连续滚动超过 40 条后，点击右侧箭头置顶，再打开详情并返回 | 无“加载更多”按钮或刷新提示，全部已有条目可连续浏览；置顶回到第一条且不误开下方新闻，详情返回保留浏览位置 |

每项记录通过/失败/未覆盖、来源链接、提示和实际结果。模型未产生相应影响时记为未覆盖，不强迫普通新闻影响日程。矛盾证据、缺日期、更新或撤回等未遇到场景另补固定输入或真实案例；合成输入必须标记。
