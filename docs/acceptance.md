# 当前能力与验收

更新：2026-10-04（America/New_York；Linux 依赖与运行入口验证）。按最新设计，首页采用一条新闻流、相关报道优先和条目内关联提示；移除独立关注区与重复关键词框，唯一搜索框移至底部，保留两页导航、菜单关注/收藏及天气。前轮底部搜索布局交付时未继续检查，本轮 Linux 验证见下方。本文件集中维护当前实现、已知缺口和验证；运行步骤见 [开发说明](development.md)，历史记录见 [归档](archive/README.md)。

## 当前实现

| 范围 | 能力与边界 |
| --- | --- |
| 新闻浏览 | 真实来源、独立缓存和错误、时间排序、同链接去重、分类/搜索、详情、收藏；顶部“首页 / 日程”导航，收藏从菜单进入，切页保留筛选。首页只有一个搜索框；筛选后稳定分组，关注匹配或有当前 Agent 待处理建议的报道优先，每组保留原顺序 |
| 启动与更新 | 只恢复启用源缓存，8 ms/最多 64 条分批处理；合并来源完成后的更新，失败保留缓存且不重排。启动刷新缺失或至少 5 分钟的来源，上拉刷新全部启用源；状态保留已有新闻数和来源进度，进行中重复上拉不取消或重启任务 |
| 关注 | 来源、主题、关键词匹配；菜单管理或筛选关注新闻。首页不另建关注区，未分析报道只说明规则匹配；匹配与缓存分析分批准备，完整且当前的结果一次提交，绘制回调只读缓存。自然语言意图与自动分析尚未实现 |
| 新闻影响分析 | 单条详情或跟踪页手动发起；每批最多 8 条，按请求快照验证结果，有取消、超时、迟到与重复回调保护。首页条目可复用当前结果的一行解释；具体日程影响指向对应建议。指纹、提示词版本、证据时效不符或建议已处理时隐藏当前提示，历史保留。分析使用标题/摘要，不宣称阅读了全文 |
| 检查反馈 | 未设置关注/日程时引导添加；刷新期间暂缓检查；无候选时明确本次未调用助手；分析后分别说明无需调整、证据不足或待确认建议。关注、来源或日程改变及刷新时清除旧检查提示，历史保留。内部成功/失败/跳过统计不占据首页 |
| 建议与决定 | 有待处理项时首页显示数量；跟踪页可查看结果与历史快照。同目标同证据建议受抑制，更新可替代旧待处理项，明确无变化可撤回，证据不足进入待复核；依赖 goal_key/内容版本，不代表语义事实核验 |
| 应用内日程 | 标题/内容/地点、北京/纽约时间、编辑、完成/取消和持久化。改期默认关闭；提议预览后再次确认才写入，复核证据、关注、许可、版本与冲突，支持重复确认和部分写入失败恢复 |
| 菜单与诊断 | 品牌左侧三横菜单提供来源、关注管理、关注动态、收藏、分析建议与天气；首页有轻量待处理建议入口，刷新中可停止新闻更新。连接测试收在来源页“连接诊断”中；测试只检查宿主连接，不证明业务分析正确 |
| 天气 | 品牌右侧小组件、逐日预报与选城。Open-Meteo、30 城、最多保存 12 城；当前城市持久化，旧选择文件兼容。独立恢复所选城市缓存、补取缺失/过期预报；失败显示原因和旧缓存，未知气温不补 0。位置说明卡片已删除；查询仍使用选城参考坐标，不读取设备位置。天气尚未接入 Agent |
| 其余信号接口 | 年度节假日与 CNY 基准汇率；独立校验、缓存与请求状态，未覆盖年份明确未知，取消/重复完成受保护；汇率按最新两日比较并限制支持币种。未接入页面、启动或 Agent，调用说明见 [信号接口](frontend-signal-api.md) |

天气联合分析、语义/向量检索、后台监测、通知、系统日历写入和跨设备同步尚未实现。当前主要以实际 Rinx 业务闭环作为下一步验收目标；包摘要、参考宿主运行和 App Hub 发布分别验证。

## 已知缺口

- 运行器仍发送内联提示词，`src/agent/prompts/news-impact-v1.md` 尚未作为执行模板加载，需统一维护方式。
- `tests/fixtures/analysis-reschedule.json` 的动作缺 `schedule_id/schedule_version`，输入日程缺 `allow_reschedule: true`，却标记 `expected.valid: true`；该 JSON fixture 尚未接入 Agent 测试入口。其他改期场景通过不能替它背书。
- 严格的关键词和日程标题召回可能漏掉相关报道；同链接的内容版本与 goal_key 也不能替代跨报道语义归并。
- 原生固定回复检查不证明真实模型质量或固定 Rinx 的取消、建议确认和重启行为；真实业务流程需按下表记录。

## 人工验收

使用固定 Rinx 和最新未签名包，退出旧应用后 **Review bundle → Run**。模型配置见 [开发说明](development.md#5-配置-rinx-自带-octos-并测试)。参考 card-host 可查无 AI 降级与固定输入 UI；不把它当成 Rinx 服务验收。

| 操作 | 应观察到的结果 |
| --- | --- |
| 启用少量来源，刷新、搜索、关注来源、收藏并重开 | 真实新闻或具体来源错误可见；关注和收藏保留；首页没有批量分析按钮或成功/失败/跳过计数 |
| 切到跟踪页，未添加关注时尝试操作；添加主题/关键词后检查 | 先引导添加关注；有上下文时可检查。没有候选只说明未调用助手，不能当成 AI 判断“无需调整” |
| 新闻正在刷新时检查，或检查过程中停止 | 刷新期间说明稍后再检查；停止后不续发剩余任务，中断未确认时明确要求重开 |
| 在相关新闻详情发起分析，期间返回动态或打开另一条，再从跟踪查看结果 | 原新闻结果仍可找到；说明依据、影响及不确定性，不自动修改日程 |
| 对同新闻再次分析，忽略已有建议后在证据未变化时再分析 | 同目标同证据不重复新增待处理项，已忽略决定保留；结果页可回看历史快照 |
| 创建未来日程并填写内容/地点，切换北京/纽约时间；保存后编辑，另建日程测试完成/取消并重开 | 时区切换保持同一时刻；内容/地点和状态持久化；完成/取消日程不占用时间 |
| 有日程动作时接受、取消预览，再接受并确认保存，最后重开 | 取消预览不写入；确认后日程和决定持久化；重复确认不重复执行；改期需先开启许可 |
| 已有改期建议时先手动编辑目标日程或关闭许可，再确认旧建议 | 拒绝旧版本或未授权动作，显示原因并保留当前日程；证据缺失、过期或变化要求刷新/重分析 |
| 助手不可用时尝试分析或“菜单 → 新闻来源 → 连接诊断 → 测试连接” | 显示真实错误，新闻、收藏和手动日程仍可用；连接诊断平时收起 |
| 顶部天气组件选城，查看预报后返回、重开；更新失败再重试，移除城市 | 显示今日预报温度范围、降水和更新状态；主城市及城市列表保留，失败不补造天气；不显示位置说明卡片，组件加载不阻塞新闻 |
| 在新闻标题或条目区域上拉、向下拖动；更新中再上拉 | 上拉启动刷新，向下不触发；重复上拉不取消或重启刷新，失败保留旧新闻；菜单可停止新闻更新 |
| 连续滚动超过 40 条后，点击右侧箭头置顶，再打开详情并返回 | 无“加载更多”按钮或刷新提示，全部已有条目可连续浏览；置顶回到第一条且不误开下方新闻，详情返回保留浏览位置 |

每项记录通过/失败/未覆盖、来源链接、提示和实际结果。模型未产生相应建议时记为未覆盖，不强行让普通新闻改期。矛盾证据、缺日期、更新或撤回等未遇到场景另补固定输入或真实案例；合成输入必须标记。
