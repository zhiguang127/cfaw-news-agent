# 分析闭环逻辑优化（2026-10-02）

## 已实现

- 批量分析与正在打开的新闻详情解耦，按请求ID和真实输入校验回复。切换页面、关闭详情和不改变内容的刷新不会误判结果过期。
- 批次词法筛选每5条让出执行预算，最多分析8条；成功/失败/跳过分开计数。取消或超时停止整个批次；中断等待最多10秒，未确认则要求重新打开应用。
- 新旧输入比较只看最近一次分析，覆盖新闻内容/来源日期语义、完整追踪规则、日程和明确用户决定，可识别A→B→A。
- 同新闻不同业务目标建议可并存；同目标同证据的已处理建议受到抑制。更新旧待处理提案会替代旧记录。goal_key缺失时只能按精确文本/动作标题兼容，不能保证语义等价。
- 证据不足保留旧建议并标记待复核，暂停接受；明确无需调整才撤回分析覆盖范围内的旧建议。
- 确认前重新读取来源缓存、检查内容/日期语义/两小时有效期/追踪规则，再读取日程版本与冲突。证据缺失、演示内容或过期不能执行。部分成功的日程写入通过建议标记恢复，避免重复创建/改期。
- 保存失败不能显示为分析成功；建议页提供重试保存。历史保存备份，损坏原件保留；未知新版本不自动降级。
- 顶部“建议”独立入口展示待处理项（每页20条）和最近30条分析。建议自身保留证据快照，即使新闻已离开列表或旧分析摘要已被清理仍能查看详情。详情显示最近30条建议及从结果页指定的旧建议。
- 合并新闻复制输出对象、保留所有来源引用并选用抓取时间较新的内容，避免修改来源缓存。
- 上下文最多8条日程/12条决定，按完整记录缩减并明确省略数量；模型输出和日程字段有长度限制。保留最近120条分析摘要；最多500条建议，用户决定及待处理项不自动删除，容量达到限制时明确停止写入。

## 使用

重新导入`build/cfaw-news.zip`。先在真实新闻详情尝试单条分析，再从动态页分析本次变化。
顶部“建议”可统一查阅；执行前请刷新相关来源。旧建议缺少完整证据版本时需要重新分析。
已有标题→内容→地点→开始/预计结束录入流程、北京默认与纽约夏令时处理保持有效。

保留的边界：跨文件写入不是数据库事务；同时打开多个应用实例不提供分布式一致性。
容量上限需要先备份再整理历史文件；当前没有自动删除用户决定或清空日程的流程。
词法候选召回和有限日程覆盖不等于全文/向量检索或所有计划已被检查。
