# 关注页面设计与实现（2026-10-11）

用户已确认本方案。10.11 版本以话题总览、话题详情和判断依据三个页面实现下述交互；实际验证记录见 `../reports/follow-topic-ui-20261012.md`。

关注页以话题为主体。进入后，用户能回答：我正在关注什么、目前获得了什么信息、这意味着什么、下一步是否需要安排；需要核对时再查看依据。首页继续承担浏览新闻的职责。

## 主页面

顶部是“我的关注”，提供“添加关注”和“检查更新”。下面依次显示用户已保存的话题，每个话题一张卡。新变化和需要核实的事项优先；其余按用户顺序显示。暂停的话题收进底部的“已暂停”。管理操作放在话题详情内。

每张卡依次展示：

1. **名称、状态和检查时间。** 名称来自用户确认的关注；本次检查状态与最近成功检查时间分别显示。
2. **目前情况。** 按已校验的产品或事件判断展示最多3条关键信息，说明进展与未知条件，避免堆砌新闻标题。话题详情保留完整文本和具体变化。界面不另行拼接未经校验的全话题结论。
3. **建议下一步。** 建议必须接续上面的事实，并对应用户的关注目的。默认突出最重要的一项；没有值得改变安排的依据时明确说“目前无需新增安排”。普通新闻跟踪不强迫用户购买、试用或核实大量规格。实际目标则可给出试用、补证或继续观察的具体下一步。
4. **查看依据。** 显示本项判断实际引用的报道数量；不是全部候选数量。完整分析和其他事项进入话题详情。

以下仅为文案示意，不代表已核实的新闻：

> **小米公司动向**　有新进展  
> 最近检查：10分钟前 · 本轮依据：3篇报道  
> **目前情况**  
> 本轮整理出两项产品动态：一项已正式发布，另一项仍处于认证阶段。现有报道尚未披露后一项的售价与开售时间。  
> **建议下一步**  
> 继续追踪正式发布消息；目前没有需要你立即处理的事项。  
> **查看依据（3篇）**　**话题详情**

## 话题详情

先展示完整的目前情况，再展示各事项的建议、缺失条件及与上次的变化。一个话题存在多个独立事件时分开说明，不能用一条建议替代整个话题的情况。

底部或更多菜单提供“修改关注、暂停、取消关注、单独检查”。用户决定针对具体建议记录，可选“继续观察、已处理、不采纳”。这些决定不删除话题，也不抹去当时的建议；新信息有实质变化时才能重新提醒。需修改日程的建议仍先预览，再由用户确认。

## 判断依据页

从卡片或具体事项的“查看依据”进入，顺序为：

1. **为什么这样判断**：哪项事实与关注目的有关，以及哪项未知条件限制了建议。
2. **支持的新闻**：标题、来源、发布时间和本次读取状态。重复报道合并显示来源，不冒充独立验证。
3. **可用证据**：来源摘要、已读取正文片段及选用原句。中文解释与原文引句分开；英文原句保留原语言。只有标题时明确标注，不伪装成摘要或全文。
4. **阅读报道**：打开应用内阅读页或原文页；返回后保留所在话题与滚动位置。

实际引用的来源中，关联尚待确认者单独标注，不额外展示未引用的候选。不能把召回关键词或分类命中当成已确认相关。先从保存的快照显示当时依据，即使新闻已退出当前首页，用户仍能核对已保存片段；原站全文是否仍可读取另行显示真实状态。

## 检查与空状态

| 状态 | 用户看到的内容 |
| --- | --- |
| 尚未检查 | 已保存的关注范围，以及“检查这个话题”入口 |
| 检查中 | 话题卡保留上次情况和时间，本次显示获取、分析或保存进度 |
| 有新进展 | 新事实、与上次的区别、是否影响下一步 |
| 暂无新增依据 | 本次有限范围内未确认新变化，不宣称外界没有新消息 |
| 证据不足 | 已获得的线索、仍缺什么、补证或继续观察的建议 |
| 本次失败 | 可理解的失败原因和重试入口；保留注明时间、尚未重新核实的上次情况 |
| 分析详情未保留 | 显示上次完成检查时间与单独重查入口，不能把已完成检查说成首次未检查 |
| 已暂停 | 保留最后情况，提供恢复入口 |

手动“检查更新”按已保存顺序逐个检查有效话题，每个话题独立召回最多8篇候选并完成分析与保存，再轮到下一个；暂停话题不参与，一项失败仍继续其他项。顶部显示话题进度，最终区分完成和未完成的数量。单独检查使用相同入口，只排当前话题。停止检查、修改关注或日程、未保存结果和宿主中断会结束后续排队；迟到回调沿原任务保护处理。原有自动检查仍受其目标预算限制，手动队列期间不插入自动任务。

每张话题卡分别显示本轮候选数、实际引用的依据数及未纳入的候选数。排队保证每个有效话题轮到一次，不保证所有候选或外界新闻已覆盖；未找到候选不能宣称话题没有新进展。

## 实施边界

总览复用原 schema 2 每话题最多3项判断及原持久化记录；展示投影不额外请求模型，也不另存一套结果。旧结果标明时间及历史状态，供回顾；基于失效、暂停或取消话题的判断不能继续操作决定、补证或日程。检查中或失败时保留上次情况并注明本次尚未完成。用户决定与原建议分别展示，观察不会覆盖实际 next_step，已处理和不采纳不再列为新的安排。

历史结果最多保留12轮，手动逐话题检查每项占一轮。较早详情离开缓存时，关注与用户决定仍保留，成功检查时间单独显示，用户可以单独重查；界面不承诺所有话题的分析详情永久留存。

判断依据只使用该话题判断实际引用并通过关联检查的报道，关联尚待确认者有独立标注。新闻退出首页后仍能读取当时保存的摘要、正文片段和引句；应用内报道页保留快照入口。返回时保留话题、原入口及滚动位置。网站当前全文读取仍由真实网络及站点权限决定，不由保存的快照推定成功。

“建议记录”保留为次级入口，承接原话题、日程及待确认事项。关注总览不再使用首页的天气、搜索、今日精选和最新文章布局，悬浮球不遮挡话题与依据操作。
