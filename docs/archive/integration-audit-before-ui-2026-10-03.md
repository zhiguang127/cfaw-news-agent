先按下方 Windows 启动、导入与模型配置说明使用固定 Rinx，退出旧应用并重新 **Review bundle → Run** 最新包。参考 card-host 用于固定场景和无 AI 降级检查，真实模型流程在 Rinx 验收。仅本轮文档修改无需重打包；拉取运行代码后仍应按打包流程刷新未签名包，Windows 启动脚本会执行该步骤。

| 操作 | 应观察到的结果 |
| --- | --- |
| 启用少量来源并刷新，搜索、跟踪、收藏后重开 | 真实新闻或具体来源错误可见，收藏与追踪保留；演示缓存有明确标记，不作为联网成功证据 |
| 创建未来日程，填写内容/地点；保存后继续编辑，切换北京/纽约时区并保存；另建日程测试完成/取消 | 切换时区保持同一时刻，记录重开后保留；完成/取消的日程保留状态且不再占用时间 |
| 在相关新闻详情点“分析影响”，等待时切回动态或打开另一条，再打开顶部“建议” | 原新闻结果仍可找到；区分有建议、无需调整和证据不足，分析只使用标题/摘要，不自动改日程 |
| 配置追踪后点“分析本次变化”；处理中取消，随后重试 | 每批最多 8 条，能看到成功/失败/跳过汇总；取消后不继续处理剩余条目，中断未确认时要求重开 |
| 对同一新闻重分析；忽略已有建议后，在证据未变化时再次分析 | 同目标同证据的建议不新增重复待处理项，已忽略决定保留；可从结果页回看历史快照 |
| 有日程动作时点“接受”，先取消预览，再重新接受并点“确认并保存”，最后重开 | 预览取消不写日程；确认成功后日程和决定持久化，重复确认不重复执行；改期必须先开启“允许 Agent 提议改期” |
| 已有改期建议时先手动修改目标日程或关闭改期许可，再确认旧建议 | 拒绝旧版本或未授权动作，保留当前日程并显示原因；新闻证据缺失、过期或变化也应要求刷新/重分析 |
| 在助手不可用的实例尝试分析或 Test Octos | 显示真实错误，新闻浏览、收藏和手动日程仍可用 |
