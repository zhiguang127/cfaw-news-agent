## 产品判断：下一步应该解决什么

目前已经能表达关注、保存日程、把相关新闻排到前面，并提示可能影响已有日程的信息。接下来要让用户得到三个明确结果：

1. **输入后及时知道进度，并更快得到可确认的理解。** 用户反馈 Agent 太慢；已有一次真实意图返回约 23 秒的记录，但尚无可比较的分阶段延迟数据。
2. **知道消息对自己的目标到底意味着什么。** “我想做…”已经保存为目标关注，但分析结果仍主要是逐条相关性和日程影响，缺少按目标汇总的决策变化与具体下一步。
3. **知道这次有什么新变化、依据有多完整。** 用户不应每次重读同一批理由，也不能把摘要推测当成已经核实的行程影响。

继续使用一个应用 Agent，由检索、持久记录和确定性校验支持。A/B 是开发分工，不增加运行时 Agent，也不引入第二个模型内核。

### B02：让“我想做…”具有决策价值

- [ ] **目标关注**：按用户确认的目的与偏好，给出“哪项判断有变化、支持它的消息、建议下一步核实什么”。允许继续观察、无需调整或证据不足；不替用户宣布目标完成，也不自动创建日程。
- [ ] **新闻关注**：说明话题出现了什么新发展、哪些消息值得读，允许没有行动建议。一般兴趣不补造工作目标。
- [ ] 同一报道面对两种意图可以有不同解释。例如框架发布新版本：目标“为离线知识库选框架”需要核对本地部署与资源条件；新闻“了解 Agent 动态”只需说明发布变化。融资消息是否提升由已确认偏好决定。
- [ ] 给目标提供一项简短、可操作的核实建议，例如“查看该版本的离线部署要求”；说明依据和未知条件，避免只返回“建议关注”。建议只是文字提案，不调用外部工具或执行目标。
- [ ] 比较对应目标 ID/版本的历史结果，保留首次检查与增量检查区别；修复跨目标误用最后一轮 previous_result 的问题。不同目标的轮换不能互相覆盖结论。

验收：同一组新闻分别输入目标与新闻关注，输出差异可解释；负面偏好有效；缺证据返回未知；保存后沿用已有收回面板和首页更新闭环。

### B03：变化摘要与决定记忆

- [ ] 复用“关注动态/分析建议”页面展示每个已检查目标最多 3 条变化，包含上次比较时间、相关报道与检查覆盖。首页最多保留一条紧凑摘要入口，不把每篇新闻展开成分析卡。
- [ ] 区分新增、更新、撤回、无实质变化；同事件多篇报道归并显示，保留各来源。转载数量不当作独立证实，不把只有 URL/发布日期变化当作新事实。
- [ ] 优先使用稳定来源标识、规范链接与内容特征去重；需要模型判断的同事件归并也必须保留原始证据，不能称为已经有向量检索。
- [ ] 扩展目标/话题级决定：“继续观察”“已处理”“忽略此变化”；通过 owner 保存，不等同于执行建议。相同变化不再提醒，实质新证据重现时解释新在哪里。
- [ ] 新结论撤回旧建议时显示撤回原因；不能只让旧卡片消失，也不能静默清除用户决定。用户修改目标后保留历史，但旧版本不继续指导当前排序。

验收：首次消息→重复转载→新增事实→用户忽略→无变化刷新→修订/撤回，分别得到正确的摘要与提醒状态。沿用现有日程决定抑制逻辑，补齐目标级能力，不重复建设一套缓存。

### B04：关键结论可以核对原文

- [ ] 首批只对用户打开的详情或高影响候选补证据，默认每轮最多 2 篇；复用已有受支持来源的提取规则，新增域名需同步新闻配置、manifest 和实际宿主网络验证。
- [ ] 将阅读页当前的全局 article_state 与分析证据分开，建立按新闻 ID/内容版本的有界证据记录。保留 URL、抓取时间、内容指纹、段落 ID、截断标记和读取失败原因。
- [ ] 模型只接收预算内的必要段落；总提示仍受现有约 32 KiB UTF-8 限制，删减完整记录并报告遗漏。正文提取仍受现有 24 KB/80 段上限约束，不把整页或付费墙当作正文。
- [ ] 结论引用新闻与段落；涉及事件日期、地点的影响说明必须能定位支持内容。确定性校验检查引用存在、版本与时段合法，事实是否支持结论另做案例审查。
- [ ] 抓取失败继续使用真实摘要，明确证据范围与不确定性；不制造全文。网页内指令仍按不可信数据处理。缓存失效和取消遵循已有任务保护。

验收：摘要缺日期但正文有明确日期、正文仍缺日期、页面失败、相互矛盾的来源、正文版本变化这五类案例。证据变化使旧分析失效，不能继续显示“已核实”。

### B05：上海旅游从城市相关走到行程核对

- [ ] 日期型行程和精确时段行程分别处理。上海预设只有首次启用两周后的日期，展示“具体时间待补充”；不把全天日期范围解释成用户乘车/飞行的时刻。
- [ ] 用户主动查看行程影响时，最多追问一项关键缺失信息，如交通方式/班次或活动区域；用户补充并确认后才更新日程版本。普通浏览不被追问打断。
- [ ] 检索优先寻找有明确地点与有效日期的交通/场馆公告；先评估已启用来源覆盖，再增加可验证的一手来源。新增订阅在应用数据层实现，不假设本地函数自动成为 Octos 工具，也不扩成任意网页抓取。
- [ ] 输出“需要核对哪一项、为何、证据、还缺什么”；只匹配上海城市名的消息可以参与初步排序，不能声称影响某班次。来源没有覆盖时显示覆盖不足，不等于行程安全。
- [ ] 天气联合判断只在行程进入现有 7 日预报覆盖范围时考虑，注明预报时间和不确定性；两周后的天气目前无法确认。节假日/汇率已有数据模块，但不在首批为了演示强行接入。

验收：明确覆盖行程日期的公告、仅涉及上海的普通新闻、过期公告、未知事件日期及未确定班次；确认补充前后版本不同，旧提醒失效。
