# Agent 接入与后续实施计划

更新：2026-10-03。当前基线为 `641910a` 加本地产品界面调整。已实现能力与验证只在 [验收记录](acceptance.md) 维护；原始分阶段设计保存在 [归档](archive/agent-integration-plan-2026-10-02.md)。

## 当前优先工作

| 优先项 | 工作 | 完成条件 |
| --- | --- | --- |
| 真实业务验收 | 在固定 Rinx 验证单条分析、跟踪检查、取消、服务不可用、建议决定和日程确认 | 有真实调用与交互证据，未覆盖项明确列出；连接测试不能代替业务验收 |
| 提示词与样例对齐 | 统一运行器实际提示词和文档模板；补齐改期 fixture 的动作 ID/版本与改期许可，并接入测试 | 生产、校验、契约及代表样例一致；固定正反输入通过 |
| Agent 价值与解释 | 用明确关注和真实新闻验收“影响什么、为什么、下一步做什么”；提高筛选原因和证据范围的可读性 | 未调用模型、无需调整、证据不足和待确认建议各自清楚，普通新闻不强行改期 |
| 调整约束 | 明确活动类型、允许调整窗口和跨新闻目标识别的产品需求 | 确定契约与执行位置，证据/版本/授权/冲突在确认时复核 |

这些工作围绕一个应用 Agent 推进。关注检查当前按词法规则召回，内容版本不是语义事实变化；升级召回或建议身份必须用代表案例验证效果，不只添加接口。

## 后续候选

天气联合分析应在新闻业务闭环验收后推进：选择授权来源、规范地点/时段/单位/有效期，缺失或过期时不产生确定改期，预报变化可更新或撤回建议。活动类型和允许调整范围需先明确。

向量/混合检索、后台触发、通知、系统日历和跨设备同步分别评估运行位置与目标宿主支持。当前文件或权限声明不代表这些服务已可用。新增原生服务或外部基础设施应单独记录运行和分发影响。

App Hub 发布另行完成 listing、图标、实际截图、隐私/支持信息、准入检查、签名与实际安装；不把包摘要或本地 Rinx 运行等同于上架。
