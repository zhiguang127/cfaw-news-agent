## 产品核心与今天的交付

**追踪就是替用户看新闻，把最关心的内容排到首页前面，Agent 解释为什么与他相关；新闻可能影响已有日程时，直接在首页提醒。**

当天必须体现三个结果：

1. **首页优先看到关心的新闻**：按用户的关注范围和偏好筛选、判断，相关报道进入同一新闻流前部，用户不用去专题详情找结果。
2. **知道为什么相关**：条目下最多一行 Agent 解释，指出对应关注和具体关系；点击查看新闻变化、完整理由、来源和不确定性。
3. **及时发现日程影响**：条目下提示“可能影响日程「……」：……”，指向具体安排及原因；有待关注影响时，首页保留一个紧凑的提醒入口。详情可以选择继续关注这类信息。

流程：表达关注 → 保存 → 应用检查新闻及已有日程 → 首页相关内容优先并解释关系/提醒日程影响 → 查看依据、继续关注或忽略 → 后续刷新沿用决定。

关注示例：

> 我在为本地知识库项目选 Agent 框架，关注开源、离线部署和资源占用，融资消息少一点。

保存“为什么关注、关注什么、判断标准”，关键词只用于召回。结果可以是值得阅读、继续观察、无需处理或证据不足，不能强迫每条新闻生成行动。一般兴趣允许没有明确目的。

日程示例（固定测试场景，非真实新闻）：用户已有“周五杭州出差”，报道涉及与行程地点和时段重合的交通限制。首页将该报道排到前面，提示“可能影响日程「杭州出差」：需核对所乘班次”，详情展示实际依据；没有明确重合或来源覆盖不足时不宣称影响已确定。

**首页排序约定**：先应用分类和搜索，再按“有当前证据支持且未忽略的日程影响 → 关注相关报道 → 普通新闻”稳定分组，组内保留时间顺序。同一报道只出现一次，不另建关注新闻框。尚未分析的规则候选可以优先，但标明匹配原因；Agent 已判断无关的报道不因旧规则继续冒充相关。AI 不可用时规则匹配和普通浏览仍可用。

当天复用现有首页、来源、详情、收藏、天气和日程表单。**已有日程的新闻影响提醒属于当天必做**；自然语言创建计划、根据新闻确认改期、后台推送、语音和向量检索留到下一轮。提醒不自动修改日程，也不要求先开改期许可。

## B：队友负责 Agent、检索和结果校验

主要改 `src/agent/` 和 `src/data/retrieval/`；保持一个应用 Agent，不操作 widgets，不直接写用户记录。

- [x] **意图整理**：解析目的、范围和偏好，返回待确认理解；信息不足最多追问一个关键问题，不编造用户目的。
- [x] **关注与日程召回**：BM25 初筛（英文词/中文二元词，k1=1.2、b=0.75，标题及最多 1,800 字符摘要；来源/分类精确门），LLM 用完整目的/偏好二次判断，并使用日程地点、内容和日期寻找候选，不仅完整匹配日程标题；每次最多 8 条候选，去重并保留来源，说明范围/遗漏，不称为向量检索。
- [x] **逐条关系与变化**：按完整关注目的和偏好判断报道是否相关，返回对应关注、具体理由和证据；融资等偏好影响判断，不只是存下来。首次说明当前证据，后续比较变化，不要求必须生成建议。
- [x] **日程影响判断**：把候选与实际日程比较，返回 schedule_id/版本、具体影响、证据及不确定性；支持只有日程没有关注的用户。缺日期或地点关系时说明未知，不强迫交通/一般新闻成为影响。
- [x] **结果校验**：校验两类结果、逐条新闻/关注/日程引用和版本；不得伪造 interest_id 通过旧校验器。标题/摘要不冒充全文，新闻内指令不授权操作；本轮结果不生成日程写入动作。
- [x] **任务保护**：复用 Octos 请求边界；全应用只允许一个推理任务，用户输入优先。处理任务关联、取消、超时、迟到和重复完成；中断确认前不发新任务。
- [x] **重复与改判**：相同输入复用成功结果，失败不记成功；已忽略建议无实质新证据不重现，新证据可修订或撤回。用固定输入验证这些行为及非法输出。

新增模块已按实际职责放入 `runtime/`、`prompts/`、`results/` 和 `data/retrieval/`；提示词必须纳入实际组装并记录 revision，不能只写 Markdown。

**给 A 的东西**：两类调用样例，逐条“相关新闻＋为什么相关＋可能影响哪项日程”的经校验结果或明确错误，以及取消入口；先交标记为测试的首页相关/无关/日程影响样例，再接真实服务。

## 第一小时共同定好的接口

以下是已实施的应用接口；不是宿主 API 参数。字段变更由 A 合并，并同时改调用方、校验和 fixtures。执行入口为 `app/intents.splash` / `app/tracking.splash`；请求边界为 `agent/runtime/tracking.splash`，旧 runtime/analysis 内联模型路径已替换。

| 对象/操作 | 约定 |
| --- | --- |
| 专题记录 | `topic_id / version / original_input / supplement / title / purpose / scope / preferences / recall_rules / status / created_at / updated_at`；purpose 可空；确认记录 active/paused，独立草稿 editing/ready/needs_clarification；待确认修改不覆盖已确认记录 |
| `parse_intent` | 输入原话、当前草稿/专题和必要补充；返回 ready 或 needs_clarification，以及整理内容/至多一个关键问题 |
| `tracking_update` | 输入关注（可空）、已有日程（可空）、候选证据、上一份结果、决定和覆盖信息；返回 update/no_change/insufficient_evidence，逐条给出 news_id、relevance（related/unrelated/uncertain）、topic_ids、why_related、证据引用及 schedule_impacts。至少有关注或日程目标，不伪造关注 |
| 日程影响 | 每项 schedule_impacts 引用已提供的 schedule_id/schedule_version，含 goal_key、impact_summary、event_start/event_end（有来源支持的 RFC3339 事件时段）、overlap_reason、evidence_ids、uncertainties、material_change；校验器拒绝缺失/非法时段和不重合事件，结构通过不证明事实正确；A 据此显示提醒并派生优先组，无需模型编造重要性分数或日程时间 |
| 提醒与决定 | 当前提醒从有效检查结果及决定派生，稳定 ID 由 schedule_id＋goal_key 生成；持久决定为 dismissed/followed，可确认关注范围，无日程执行动作。更新/撤回或失效后旧提醒隐藏，旧建议状态继续由兼容读取器加载 |
| 请求与错误 | 应用生成 task_id、任务类型、目标 ID/版本、输入指纹；最多一次终态；返回真实服务/超时/解析/引用错误，不把失败当作无变化 |

B 拒绝旧请求完成，A 保存前再次核对版本。专题/检查时间使用 Unix 秒，日程起止时间沿用现有 RFC3339 与时区契约，未知发布日期保持未知。结构合法不等于事实正确。

工作指纹包含关注与日程 ID/版本/状态、候选 ID/内容版本、提示词/配置版本和决定；仅抓取时间改变不触发分析，保存本次结果不改变同输入指纹。新报道或内容变化只触发重评，重新提示已忽略提醒还须说明实质新证据。来源 URL、发布日期和证据类型变化也使旧依据失效。

保存/修改关注或日程、缓存恢复完成、整轮刷新结束触发有限检查；只处理变化，不在绘制或每个来源回调里调用模型。无候选不调用模型。初始上限：20 个新专题、每轮检查 2 个关注/日程目标（按成功检查时间轮换）、每次最多 8 项相关日程、输入 1,000 字符、6 条召回规则；BM25 至多 24 个查询词；缓存至多 12 次检查，决定至多 200 条。超限显示覆盖和待检查范围，不能声称全部日程已检查。配置集中在 `src/app/config.splash`，请求体缩减完整记录，不截断 JSON。
